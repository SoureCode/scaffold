# Project goals

- Build a **reusable toolkit of Symfony extensions** — anything that recurs across our Symfony projects, packaged once and shared.
- Cover **any area** of a Symfony app over time (persistence, security, messaging, console, UI, …), not only Doctrine. Doctrine behaviors are just the current crop.
- Stay **opinionated and convention-driven** — minimize boilerplate at the call site. The user marks an intent (attribute, trait, interface), the framework does the wiring.
- Keep every capability **decoupled from the framework when it can be**: ship a plain PHP component first, layer the Symfony bundle on top. Each layer is independently understandable.
- Keep the toolkit **one install boundary**. Everything ships and versions together; consumers depend on the monorepo, not on individual sub-packages.
- Stay **current**: latest stable PHP and Symfony. No backwards-compat shims, no legacy code paths.
- Treat the codebase as a **shared foundation** for other SoureCode work — anything that's been built twice in different apps is a candidate to live here.

# Non-goals

- **Not a generic "do everything" library.** We add a capability when we actually need it more than once. No speculative APIs.
- **Not split-installable.** No `composer require sourecode/<single-package>` workflows. Consumers take the monorepo.
- **Not framework-agnostic at the top level.** The end product targets Symfony. Components stay framework-agnostic where the cost is low; bundles do not pretend to work without Symfony.
- **Not Symfony 7 or older. Not PHP < 8.5. Not Doctrine ORM 2.x.
- **Not a competitor to large existing products.** When something else already does the job well (full audit logging, full event sourcing, full search engines), we don't reimplement it — we either depend on it or stay out of that space.
- **Not a place for one-off project code.** If it's used by exactly one app, it belongs in that app, not here.
- **No backwards-compatibility promises until a capability has stabilized.** Breaking changes are expected during a capability's early life.

# Working conventions

- Layout: `src/SoureCode/Component/<Name>/` for framework-agnostic libraries, `src/SoureCode/Bundle/<Name>Bundle/` for Symfony bundles.
- Root `composer.json` is generated by `bin/merge` from each sub-package's own `composer.json`. Per-package files are the source of truth; the root file is never hand-edited.
- Tests run from the monorepo root: `vendor/bin/phpunit`.
- Bundles register themselves through Symfony Flex via `"type": "symfony-bundle"`. No bundle entries in user `config/bundles.php`.
